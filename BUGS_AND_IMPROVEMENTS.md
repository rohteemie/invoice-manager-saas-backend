## Critical Issues

### 1. Deprecated `datetime.utcnow()` Usage (353 Warnings)

**Severity:** Critical  
**Impact:** High - Will break in future Python versions  
**Status:** ⚠️ Not Fixed

**Description:**  
The application uses the deprecated `datetime.utcnow()` method in multiple locations. Python 3.12+ has deprecated this in favor of timezone-aware datetime objects.

**Affected Files:**
- `app/core/security.py` (lines 59, 61, 89, 91, 132)
- `app/api/v1/endpoints/auth.py` (line 264)
- `tests/test_email_verification.py` (lines 243, 244, 274)

**Current Code:**
```python
expire = datetime.utcnow() + timedelta(minutes=settings.ACCESS_TOKEN_EXPIRATION)
```

**Recommended Fix:**
```python
from datetime import datetime, timezone

expire = datetime.now(timezone.utc) + timedelta(minutes=settings.ACCESS_TOKEN_EXPIRATION)
```

**Additional Occurrences:**
- `app/api/v1/endpoints/invoices.py` - Uses `datetime.now()` instead of timezone-aware datetime
- `app/models/general_model.py` - Uses `datetime.now()` for timestamps
- `app/services/pdf_generator.py` - Uses `datetime.now()` for PDF generation
- `app/tasks/invoice_tasks.py` - Uses `datetime.now()` for task timestamps

**Files to Update:**
1. `app/core/security.py` - 5 occurrences
2. `app/api/v1/endpoints/auth.py` - 1 occurrence  
3. `app/api/v1/endpoints/invoices.py` - 3 occurrences
4. `app/models/general_model.py` - 3 occurrences
5. `app/services/pdf_generator.py` - 1 occurrence
6. `app/tasks/invoice_tasks.py` - 5 occurrences
7. `tests/test_email_verification.py` - 3 occurrences

### 2. Empty Initial Migration

**Severity:** Critical  
**Impact:** High - Database initialization issues  
**Status:** ⚠️ Not Fixed

**Description:**  
The initial migration file `migrations/versions/285ea17a7a31_initial_migration.py` contains empty `upgrade()` and `downgrade()` functions, which means the database schema is not being managed by Alembic migrations.

**Current State:**
```python
def upgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    pass
    # ### end Alembic commands ###

def downgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    pass
    # ### end Alembic commands ###
```

**Impact:**
- Database schema is created via `Base.metadata.create_all()` instead of migrations
- No version control for database schema changes
- Cannot rollback schema changes
- Difficult to track database history
- Production deployments will fail if migrations are required

**Recommended Fix:**
1. Create proper initial migration with all tables
2. Ensure subsequent migrations build on this base
3. Document migration strategy in deployment guide

### 3. Print Statements Instead of Logging

**Severity:** Medium-High  
**Impact:** Medium - Production monitoring issues  
**Status:** ⚠️ Not Fixed

**Description:**  
Several core modules use `print()` statements instead of proper logging, which will not be captured in production logging infrastructure.

**Affected Files:**
- `app/core/sentry.py` (lines 29, 31)
- `app/core/cache.py` (lines 23, 57, 80, 101, 125)

**Current Code:**
```python
print(f"Redis connection failed: {e}. Caching disabled.")
print(f"Cache set error: {e}")
```

**Recommended Fix:**
```python
import logging

logger = logging.getLogger(__name__)
logger.warning(f"Redis connection failed: {e}. Caching disabled.")
logger.error(f"Cache set error: {e}")
```

## High Priority Issues

### 4. Missing Error Handling in Email Verification Token Comparison

**Severity:** High  
**Impact:** Medium - Security and user experience  
**Status:** ⚠️ Not Fixed

**Description:**  
The email verification token expiration check in `app/api/v1/endpoints/auth.py` (line 264) compares a datetime with timezone info against `datetime.now()` without timezone, which can cause inconsistent behavior.

**Current Code:**
```python
if (user.verification_token_expires_at and 
    user.verification_token_expires_at < datetime.now()):
```

**Issues:**
- `verification_token_expires_at` is set with `datetime.utcnow()` (deprecated)
- Comparison uses `datetime.now()` (local time)
- Timezone mismatch can cause incorrect expiration checks

**Recommended Fix:**
```python
from datetime import datetime, timezone

if (user.verification_token_expires_at and 
    user.verification_token_expires_at < datetime.now(timezone.utc)):
```

### 11. Hardcoded Invoice Number Format

**Severity:** Low  
**Impact:** Low - Flexibility  
**Status:** ⚠️ Not Configurable

**Description:**  
Invoice number format is hardcoded and cannot be customized per tenant.

**Current Code:**
```python
def generate_invoice_number(db: Session, tenant_id: str) -> str:
    count = db.query(InvoiceModel).filter(
        InvoiceModel.tenant_id == tenant_id
    ).count()
    date_str = datetime.now().strftime("%Y%m%d")
    number = f"INV-{date_str}-{count + 1:04d}"
    return number
```

**Issues:**
- Format cannot be customized per tenant
- Potential race condition with concurrent invoice creation
- Count-based numbering can have gaps
- No support for prefix customization

**Recommendations:**
1. Add invoice number format to tenant settings
2. Use database sequence or atomic counter
3. Support custom prefixes per tenant
4. Add invoice number validation
